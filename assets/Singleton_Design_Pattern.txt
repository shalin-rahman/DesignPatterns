THE CONCEPT
What is the Singleton pattern?
Ensure a class has only one instance, 
and provide a global point of access to 
it.
A N A L O G Y
A country has one official government. Whoever 
holds office, “The Government of X” is the single, 
global point of access.
Also known as: “initialization on first use”, the instance is created 
just in time, when first requested.

Singleton Design Pattern
3
THE CONCEPT
Two problems, solved at once
1
Exactly one instance
Control access to a shared resource such as a 
database or a file. A regular constructor always 
returns a new object, so a different mechanism 
is needed.
2
One global access point
Like a global variable, the instance is reachable 
from anywhere, but unlike a global variable, no 
other code can overwrite it.
Because one class handles both jobs, Singleton bends the Single Responsibility Principle, a trade-off 
we will revisit at the end.

THE RACE CONDITION
Reproducing the race in Java
 
import java.util.Set;
import java.util.concurrent.*;
 
public class RaceDemo {
    public static void main(String[] args) throws Exception {
        ExecutorService pool = Executors.newFixedThreadPool(5);
        CountDownLatch start = new CountDownLatch(1);
        Set<Object> seen = ConcurrentHashMap.newKeySet();
 
        for (int i = 0; i < 5; i++) {
            pool.submit(() -> {
                start.await();  // release all threads together
                seen.add(DatabaseConnection.getInstance());
                return null;
            });
        }
        start.countDown();
        pool.shutdown();
        pool.awaitTermination(5, TimeUnit.SECONDS);
        System.out.println("Distinct instances: " + seen.size());
    }
}

REFACTORED SOLUTION
Refactored: a thread-safe Singleton
 
public class DatabaseConnection {
    private static int opened = 0;
 
    private DatabaseConnection() {  // private!
        opened++;
        System.out.println("Opening DB connection...");
    }
 
    private static class Holder {  // lazy
        static final DatabaseConnection INSTANCE =
                new DatabaseConnection();
    }
 
    public static DatabaseConnection getInstance() {
        return Holder.INSTANCE;
    }
 
    public void query(String sql) {
        System.out.println("Running: " + sql);
    }
 
    public static int getOpened() { return opened; }
}

Singleton Design Pattern
20
JAVA IMPLEMENTATIONS
3 · Double-checked locking
 
public class Singleton {
    private static volatile Singleton instance;
 
    private Singleton() { }
 
    public static Singleton getInstance() {
        if (instance == null) {  // check 1: no lock
            synchronized (Singleton.class) {
                if (instance == null) {  // check 2: locked
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
dcl/Singleton.java
W H Y T W O C H E C K S ?
1
Check 1 (no lock)
After creation, callers skip the lock: the 
fast path.
2
Check 2 (inside lock)
Stops a second waiting thread from 
creating another object.
3
volatile
Prevents reordering, so no thread sees a 
half-built object.
Bill Pugh’s work on this idiom led to Java 5 memory-model changes, and to the safer holder idiom on the next 
slide.

4 · Holder idiom (Bill Pugh)
RECOMMENDED
 
public class Singleton {
    private Singleton() { }
 
    private static class Holder {
        static final Singleton INSTANCE =
                new Singleton();
    }
 
    public static Singleton getInstance() {
        return Holder.INSTANCE;
    }
}
holder/Singleton.java
W H Y I T I S T H E S T A N D A R D
Lazy  The nested class is not loaded until 
getInstance() runs.
Thread-safe  The JVM runs class initialization exactly 
once.
Simple  No volatile, no synchronized, works in every 
Java version.
1
Application starts
Singleton is loaded. Holder is NOT 
loaded, no instance yet.
2
First getInstance() call
The method touches 
Holder.INSTANCE for the first time.
3
JVM loads Holder
INSTANCE is created exactly once 
and cached for ever.

5 · Enum singleton
 
public enum Singleton {
    INSTANCE;
 
    public void doSomething() {
        System.out.println("Doing something...");
    }
}
 
// usage
Singleton.INSTANCE.doSomething();
enumtype/Singleton.java
Thread-safe
The JVM creates each enum constant exactly 
once.
Reflection-proof
Java refuses to create enum objects via reflection.
Serialization-safe
Deserializing an enum returns the same constant.
Limitation: an enum cannot extend another class (it may 
implement interfaces), and it is created on first use of the 
enum class.
Often the simplest and safest choice when 
you do not need a base class.

HARDENING
Four ways a Singleton gets broken
Reflection
Attack  setAccessible(true) opens the private constructor.
Defense  Throw in the constructor if an instance exists, or 
use an enum.
Serialization
Attack  Deserializing an object builds a brand-new instance.
Defense  Add readResolve() that returns the instance, or use 
an enum.
Cloning
Attack  A Cloneable Singleton can be copied with clone().
Defense  Do not implement Cloneable (or make clone() 
return the instance).
Several class loaders
Attack  Each class loader can load its own copy of the class.
Defense  Keep the class in one loader, or accept one 
instance per loader.

import java.io.*;
import java.lang.reflect.Constructor;
 
public class BreakDemo {
    public static void main(String[] args) throws Exception {
        ConfigManager one = ConfigManager.getInstance();
        // Attack 1: reflection
        Constructor<ConfigManager> c =
                ConfigManager.class.getDeclaredConstructor();
        c.setAccessible(true);
        System.out.println("Reflection: same object? "
                + (c.newInstance() == one));
        // Attack 2: serialization round-trip
        var bytes = new ByteArrayOutputStream();
        var out = new ObjectOutputStream(bytes);
        out.writeObject(one);
        out.close();
        var in = new ObjectInputStream(new ByteArrayInputStream(
                bytes.toByteArray()));
        Object copy = in.readObject();
        System.out.println("Serialization: same object? "
                + (copy == one));
    }
}

HARDENING
Hardened: guards, or just use an enum
 
import java.io.Serializable;
 
public class ConfigManager implements Serializable {
    private static final ConfigManager INSTANCE =
            new ConfigManager();
 
    private ConfigManager() {
        if (INSTANCE != null) {  // reflection guard
            throw new IllegalStateException(
                    "Already created!");
        }
    }
 
    public static ConfigManager getInstance() {
        return INSTANCE;
    }
 
    private Object readResolve() {  // serialization guard
        return INSTANCE;
    }
}

    void query(String sql);

Key

1
Singleton = one instance + one global access point: 
private constructor, private static field, public static 
accessor.
2
The classic lazy version fails under concurrency, we

3
In Java, prefer the holder idiom or an enum; avoid hand-

do it for you.
