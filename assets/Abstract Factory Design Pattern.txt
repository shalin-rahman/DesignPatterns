04 · STRUCTURE
The five participants
1
Abstract Products: interfaces for the distinct products that make up a family.
2
Concrete Products: implementations of each abstract product, grouped by variant.
3
Abstract Factory: declares one creation method per abstract product.
4
Concrete Factories: one per variant; each creates only that variant’s products.
5
Client: works with any factory or product through the abstract interfaces.

05 · EXAMPLE
Pseudocode: client and start-up
class Application
    constructor(factory: GUIFactory)
        this.factory = factory
    createUI()
        button = factory.createButton()
    paint()
        button.paint()
// at start-up: pick the factory once
config = readApplicationConfig()
if (config.OS == "Windows") factory = new WinFactory()
else if (config.OS == "Mac") factory = new MacFactory()
app = new Application(factory)
Why it works
Application knows only GUIFactory, 
Button and Checkbox.
The factory is chosen once, at start-
up.
New OS? Add a factory and 
products; the client is untouched.

CASE STUDY · JAVA
Version 2: one factory per product
class CarCreator {
    static Car create(String region) {
        return isNA(region) ? new Sedan() : new SUV();
    } }
class SpecificationCreator {
    static CarSpecification create(String region) {
        return isNA(region)
            ? new NorthAmericaSpecification()
            : new EuropeSpecification();
    } }
Car car = CarCreator.create("NorthAmerica");
var spec = SpecificationCreator.create("Europe");
// compiles, but the pair is mismatched!
Better, but…
The client now uses only interfaces.
The two factories are independent, 
so they can disagree.
A new region means editing every 
factory.

CASE STUDY · JAVA
Abstract Factory in the Java code
interface CarFactory {
    Car createCar();
    CarSpecification createSpecification();
}
class NorthAmericaCarFactory implements CarFactory {
    Car createCar() { return new Sedan(); }
    CarSpecification createSpecification() {
        return new NorthAmericaSpecification(); }
}
// client: the only line naming a concrete class
CarFactory f = new NorthAmericaCarFactory();
f.createCar().assemble();
f.createSpecification().display();
What to notice
Both methods return abstract types.
One factory object, so car and spec 
always match.
EuropeCarFactory returns SUV + 
EuropeSpecification.

06 · APPLYING IT
When to use Abstract Factory
Families of related products
Your code must work with several families 
but should not depend on their concrete 
classes, because they are unknown up front 
or you want room to extend.
Factory methods crowd a class
A class with many factory methods blurs its 
main job. Extract them into a stand-alone 
factory or a full Abstract Factory.

FACTORY METHOD VS ABSTRACT FACTORY
The key question: one product or a family?
Factory Method
Creates one product. A subclass overrides a 
single method to decide which class to create.
Abstract Factory
Creates a family of related products. A 
factory object decides the variant of every 
product at once.
“Factory pattern” here means Factory Method (GoF). A Simple Factory is just a static method with a conditional, as in Version 2 of the car 
case study.

FACTORY METHOD VS ABSTRACT FACTORY
The same car domain, two patterns
Factory Method
abstract class Dealer {
    abstract Car createCar();
    void deliver() {
        createCar().assemble();
    }
}
class NorthAmericaDealer extends Dealer {
    Car createCar() {
        return new Sedan();
    }
}
// subclass decides: ONE product
Abstract Factory
interface CarFactory {
    Car createCar();
    CarSpecification createSpecification();
}
class NorthAmericaCarFactory implements CarFactory {
    Car createCar() { return new Sedan(); }
    CarSpecification createSpecification() {
        return new NorthAmericaSpecification();
    }
}
// object decides: a FAMILY of products

FACTORY METHOD VS ABSTRACT FACTORY
Which one should you use?
Use Factory Method when…
You create one kind of product and want 
subclasses to choose its concrete class.
Use Abstract Factory when…
Several products are created together and 
must always match each other.
They combine: an abstract factory’s create methods are often factory methods. Many designs start with 
Factory Method and grow into Abstract Factory.

07 · RELATED PATTERNS
How it relates to other patterns
Pattern
Relationship to Abstract Factory
Factory Method
Designs often start with it, then evolve into Abstract Factory.
Builder
Builds step by step; Abstract Factory returns products at once.
Prototype
Can implement the creation methods of an abstract factory.
Facade
Alternative when you only need to hide object creation.
Bridge
The factory hides which implementations an abstraction needs.
Singleton
Concrete factories are often implemented as singletons.
